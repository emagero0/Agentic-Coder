Welcome to OpenCode

Your new AI coding companion awaits

🎯 What is OpenCode?

OpenCode is a universal AI agent system designed to help you with code, documentation, tests, and workflow coordination. Think of it as having a team of specialized AI assistants, each expert in their domain, working together under one coordinator.

🌟 Core Capabilities

⌨️
Code Writing

Implement features, fix bugs

🔍
Code Review

Security, quality checks

🧪
Testing

TDD, coverage focus

📝
Documentation

Clear, helpful docs

💡 Key Principles

🛡️ Safety First

Always check permissions, load context, and use approval gates before making changes.

📢 Report Before Fix

Never auto-fix. Report issues and wait for your approval before making changes.

🔎 Context-First

Always discover project standards before writing code. This ensures consistency.

⚡ Be Lean

Concise responses. If it can't be understood in under 30 seconds, it's too long.

💡
Getting Started Tip
Start with a simple task to get familiar with how OpenCode works. Ask a question first (conversational path), then try a small coding task (task path with approval). This helps you understand the two main interaction patterns.

Understanding the System

How OpenCode thinks and works

🧠 The Big Picture

OpenCode operates as a hierarchical agent system. At the center is OpenAgent, the main coordinator that routes tasks, manages workflows, and ensures everything works together. Around it are specialized agents, supervisors, and tools.

System Overview

🎛️ OpenAgent (Primary Orchestrator)
Specialists
⌨️ CoderAgent | 🔍 CodeReviewer | 🧪 TestEngineer
📝 DocWriter | 📋 TaskManager | 🔧 BuildAgent
Scouts
🔎 ContextScout | 📚 ExternalScout
Supervisors
👁️ meta | 🏗️ architecture | 🧹 memory | 📊 project | 🔬 rnd | 🔗 graph

🔄 Agent Behavior Modes

Each agent has a specific behavior mode that defines how it operates:

Agent Behavior Mode Internal Loop
OpenAgent Orchestration Analyze → Route → Monitor → Report
CoderAgent Sequential Implementation Read context → Implement → Validate → Refine
CodeReviewer Checklist-based Scan → Compare to standards → Flag → Report
TestEngineer TDD Cycle Write test → Run → Implement → Run → Coverage
TaskManager Decomposition Analyze → Break into tasks → Track dependencies
ContextScout Discovery Read navigation → Match patterns → Return paths
ExternalScout Fetch-then-cache Query API → Store → Return
ℹ️
ContextScout is Special
ContextScout is the only agent exempt from the approval gate. It runs automatically to discover project standards before any task is executed. This ensures OpenCode always has the right context before making changes.

The Supervisors

Silent guardians watching over the system

Supervisors don't execute tasks directly. Instead, they monitor and guide the primary agent's decisions, ensuring quality, consistency, and proper system behavior.

👁️ Supervisor Overview

Supervisor Role What They Do
meta-supervisor Orchestration Oversight Ensures overall system coherence and coordination
architecture-supervisor Pattern Guardian Detects code drift, naming inconsistencies, architectural issues
memory-curator Context Manager Maintains context hygiene, deduplication, updates agent capabilities
project-manager-supervisor Quality Auditor Feature auditing, route analysis, project health metrics
rnd-supervisor Research Tracker Tracks R&D activities, catalogs findings, maintains knowledge base
graph-query-engine Relationship Mapper Graph-based queries for complex relationships and dependencies

🧪 Deep Dive: R&D Supervisor

The R&D Supervisor is your research companion. It tracks investigations, stores findings, and helps you avoid re-researching the same topics.

🔄 R&D Workflow

  1. You ask about a technology or approach
  2. R&D Supervisor checks the knowledge base for prior research
  3. If found, returns cached results instantly
  4. If not found, creates investigation folder and researches
  5. Catalogs findings with comparison, verdict, and recommendations
  6. Updates knowledge base for future queries

📁 R&D Storage Structure

# Where research is stored .tmp/rnd/ ├── investigations/ │ └── 2026-05-12-orm-comparison/ │ ├── findings.md # Raw research data │ ├── comparison.md # Side-by-side analysis │ └── verdict.md # Final recommendation ├── experiments/ │ └── zustand-test/ │ ├── setup.md │ └── results.md └── knowledge-base/ └── topics/ ├── react.md # Cross-linked topics ├── database.md └── api-design.md
💡
When R&D Supervisor Activates
• ExternalScout fetches library docs → Catalog findings
• explore agent discovers patterns → Track in knowledge base
• New technology evaluation → Create investigation folder
• Experiment attempted → Log to experiments/

🏗️ Architecture Supervisor

This supervisor ensures your code follows established patterns and doesn't drift from project conventions.

Detection Areas

  • 📛

  • 🏛️

  • ⚠️

  • 🔧
    Inconsistent error handling — Mixed approaches

🎯 Context Loading Workflow

Before any task executes, context is loaded to ensure quality and consistency:

  1. DISCOVER — ContextScout finds relevant paths (read-only)
  2. PROPOSE — Show lightweight summary of approach
  3. APPROVE — Wait for user confirmation
  4. INIT — Create session directory + context file
  5. DELEGATE — Pass context to specialist agents
  6. CLEANUP — Ask user, then delete session

🤝 Multi-Agent Coordination

Coordination Patterns

1. Sequential Handoff

Each agent waits for the previous to complete, then uses their output as input.

CoderAgent → implement API → TestEngineer → write tests → DocWriter → document
2. Parallel Execution

Independent tasks run simultaneously, then results are assembled.

Widget1 + Widget2 + Widget3 → parallel → CoderAgent → assemble
3. Expert Review

CodeReviewer validates output before continuing.

CoderAgent → CodeReviewer → [issues?] → CoderAgent fixes → CodeReviewer re-reviews

The Priority System

Safety → Workflow → Optimization

OpenCode has three priority tiers. Tier 1 always takes precedence over Tiers 2 and 3.

🛡️ Tier 1: Safety & Approval Gates

Always First

Priority: MAX

This tier ensures safety mechanisms are in place before any action is taken. It runs before everything else.

What's included:
  • Permission verification
  • Context loading mandate
  • Approval gate checks
  • Safety validation

⚙️ Tier 2: Core Workflow

Main Execution

Priority: NORMAL

The standard task execution flow. Only runs after Tier 1 is satisfied.

1. Analyze
→
2. Approve
→
3. Execute
→
4. Validate
→
5. Summarize

🚀 Tier 3: Optimization

Performance

Priority: LOW

Speed and efficiency optimizations. Only applies after Tiers 1 and 2 are complete.

What's included:
  • Minimal session overhead
  • Quick responses
  • Efficient processing
  • Session files only when delegating
⚠️
The Rule
If speed conflicts with quality, quality wins. Tier 1 always overrides Tiers 2/3. Never skip safety checks for the sake of speed.

Chapter 11

Best Practices

Get the most out of OpenCode

✅ Do's

🎯 Be Specific

Clear requests get better results. Instead of "fix the auth", say "add JWT token validation to the login endpoint".

🔎 Context-First

Let ContextScout find standards before writing code. This ensures consistency with your project's patterns.

✅ Review Proposals

Always check proposals before approving. This gives you control and prevents unintended changes.

📋 Track Complex Tasks

Use TaskManager for multi-step features. Breaking things down helps track progress and dependencies.

📢 Report Issues

When OpenCode finds issues, report them. Don't auto-fix — wait for your approval to proceed.

🧪 Test Thoroughly

Use TestEngineer for comprehensive test coverage. Good tests prevent regressions and document behavior.

❌ Don'ts

🚫 Skip ContextScout

Writing without standards leads to inconsistency. Always discover project conventions first.

🚫 Auto-Fix Without Asking

You may not want the fix. Always propose, wait for approval, then execute.

🚫 Be Verbose

Keep it scannable — under 30 seconds to understand. Concise is better than verbose.

🚫 Skip Approval Gates

Safety mechanisms exist for good reason. Don't bypass approval for speed.

📝 Report-First Workflow

When You Find an Issue

# ❌ DON'T: "I noticed X, fixing it now..." # ✅ DO: "I found X. This is a problem because Y. I propose to fix it by Z. Shall I proceed?"
